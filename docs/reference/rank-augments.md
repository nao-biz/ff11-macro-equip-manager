# Rank付き装備の追加能力

DATA-003・DATA-005 / D-16・D-17。Bundle形式（extdata先頭が`03 83`）の追加能力を、保存済みExportの生データとインストール済みゲームDATから解決する。個体詳細・インベントリ・装備集計・候補比較で同じ結果を使う。Exportと個体情報ストアの形式はv1のまま、原文を保持する。

## データと形式

- Rank表: FTABLEの論理ID `0x51`。確認環境では `ROM/118/114.DAT`。`menu`に続く`mnc2`チャンクを検証し、チャンク範囲内だけで参照する。
- 日本語能力書式: 論理ID `0xD914`。既存のd_msg読込を使う。
- extdataのオフセット4にある32bit値からPath（下位2bit）、Rank（18〜22bit）、上限段階（23〜24bit）を得る。オフセット8の32bit値が能力束ID。いずれもlittle endian。ExportのPath・Rankとの一致を確認する。
- 能力束はファイルオフセット176から1,024件、各12バイト（16bitのレコード参照6個）。参照0は空。能力レコードは12464から各76バイト。オフセット8が能力ID、10がパラメータ、12からRank 0〜30の符号付き16bit値31個。現在Rankの値が0ならその効果はまだ有効でない。
- 通常能力は辞書の`%d`・`%+d`・`%%`を展開する。複合書式は同じ値を各数値欄へ渡す。パラメータ形式2049〜2056は能力選択のビットマスク、2064〜2069は対象接頭辞、2076は特定WSとダメージ、4096は全基本ステータスとして解釈する。選択順と書式IDは形式定義であり、装備別の数値マスターを保持しない。

表・辞書は起動・再読み込みの共通ワーカーで取得し、Snapshotの取得元にパス・ハッシュを残す。表示・候補選択時は読み込んだ表だけを使う。既存の収納・位置・種類IDの照合後に能力を利用し、JSON中の能力文字列とDAT解決値を重複加算しない。

能力欄は追加能力と取得不足を表示し、Path・Rankは個体識別行に置く（D-18）。取得情報の専用欄は設けず、参照元・取得日時は詳細から確認する。

未知の能力束、未取得の表、書式欠落、パラメータ未対応、Path・Rank不整合は取得不足として示す。解決できた能力は保持する。ペット・特定WSの接頭辞は原文に残し、既存集計器で条件付き効果として扱う。

## 解析根拠と検証

[LandSandBoatの能力束定義](https://github.com/LandSandBoat/server/blob/base/scripts/data/augments.lua)のMNC2オフセット説明と、[パラメータ形式](https://github.com/LandSandBoat/server/blob/base/scripts/enum/augment.lua)、[extdata構造](https://github.com/LandSandBoat/server/blob/base/src/map/items/exdata/augment_bundle.h)を2026-11-09に確認した。数値表や実装コードを配布物へ転記せず、形式の根拠として利用する。実行時の能力値と日本語は利用者のゲームDATから取得する。

`tests/test_rank_augments.py`は合成MNC2・辞書によって全Rank、複合能力、割合、負数、対象付き効果、欠落・破損・未知形式、原文保持、保存後の復元、辞書再読込、二重加算防止を確認する。`tests/test_rank_augments_ui.py`は本体Tk画面の単体値とインベントリ表示を合成データで確認する。

2026-11-09の読取確認では、指定JSONに含まれるBundle形式39個の能力を解決できた。アグゥゲージのRank 8は魔攻+8・マジックバーストダメージII+2。本体説明と合わせた魔攻は43、MBダメージは8、MBダメージIIは2として別々に集計した。読み取ったDATの変更検出は0件。個人JSONとゲーム資産はGitへ登録しない。実ゲーム画面との全装備・全Rankの一致確認は未実施。
