# 個体情報の出力形式 v1

DATA-003 / D-16。UTF-8 JSON、上限4 MiB。形式名 `ff11-inventory-export`、versionは1。

ルート: format, version, captured_at（UTC ISO8601、Z）, character（id: 1..4294967295, name, server:整数）, bags（17要素）。
収納: id（0..16、重複不可）, state（ready/unavailable/incomplete）, items（配列）。
個体: index（1..80、収納内重複不可）, item_id（1..65534）, count（1以上の整数）, extdata（24バイトの小文字hex）, decode_state（decoded/unsupported/error）, augments（文字列配列）, path（A..Dまたはnull）, rank（0..127またはnull）。
未取得収納のitemsは空配列。decodedはライブラリの解釈成功を意味する。能力の全文を得られる範囲はライブラリに従い、Pathだけの結果もある。生データは保持する。

Bundle形式のRank付き装備は、アプリが生データとゲーム内DATから現在Rankの追加能力を解決する。[Rank能力](rank-augments.md)を参照する。既存JSONをそのまま利用できる。

取り込みはログイン観測で登録済みのキャラID・サーバーと照合する。USERフォルダIDからキャラIDを推定しない。各収納のローカル取得状態が取得済みであり、全位置・種類IDが出力と一致する場合だけ補助情報を公開する。日時を常時付記し、同種類の入替と取得後の強化には再取得が必要なことを取り込み時に示す。

## 自動Exportと自動取り込み

1. アプリでWindowerフォルダを選択して保存する。同梱アドオンの配置と `scripts/init.txt` の `lua load ff11export` 登録をまとめて行う。
2. ログイン・エリア移動後、所持品取得完了とキャラ情報の安定を確認して自動出力する。起動途中で導入・再ロードした場合は一度エリア移動する。
3. ゲーム利用中は所持品更新をまとめて自動出力し、ログアウト直前にも未出力の更新を保存する。アプリはゲーム終了後、変更を検出してDATと最新Exportを自動で読み込み、キャラ名と個体情報を反映する。

## Windowerフォルダの設定

初回起動時に「設定 — Windowerフォルダ」を表示する。「フォルダを選択…」で `Windower.exe` のあるフォルダを選び、「保存」を押す。保存時に同梱Luaファイル4個を `addons/ff11export` へ配置し、`scripts/init.txt` に自動ロードを設定する。アプリはその中の `data` をExport先として使う。「あとで設定」を選ぶと、次回起動時に再び案内する。

変更するときは画面右上の「設定」を開く。保存後は新しいExport先を確認し、次回起動にも設定を引き継ぐ。入力不正・取消・保存失敗では元の設定を保持する。編集中のマクロやUndo履歴は保持する。

設定はアプリ専用の `work/drafts/windower-settings.json` に保存する。設定v2には配置先と `deployment`（完了・アドオン版・同梱ファイルの指紋・自動ロード手順版）を記録する。同じ配置先・同じ指紋の完了記録があれば、再配置と設定の書き直しを省略する。同梱内容の更新、配置先変更、完了記録のない旧設定では、フォルダ保存時に導入する。通常起動や取り込みでは導入処理を行わない。従来v1はそのまま読める。

変更する既存ファイルは `work/drafts/windower-backups/<識別子>/` にバックアップする。init.txtの既存バイトと改行を保持し、既存の有効な `lua load ff11export` / `lua l ff11export` があれば追加を省く。Exportデータ・他アドオン・診断有効化ファイルは保持する。配置または設定保存に失敗した場合は変更済みファイルを戻し、完了を記録しない。復旧失敗時はバックアップ場所を通知する。プロセス中断後は次回保存で再試行できる。手動で設置ファイルを削除した後に再導入する場合は、コンフィグの `deployment` を削除して再保存する。

アプリはゲーム終了中に設定を保存する。次回のWindower起動から自動でロードされる。

初回のキャラ対応登録は次節の手順で行う。

初回導入後にExportがまだ生成されていない場合は、「ゲームにログインすると自動取得されます。ゲーム終了後に自動で反映されます。」と案内する。アドオンの配置先があり、dataフォルダが未作成の状態も取得待ちとして扱う。破損・キャラ対応不一致・アクセス失敗・配置先自体の消失は警告で通知する。取り込み済み情報は保持し、取得済み情報がある状態で元Exportが削除されただけの場合は案内を繰り返さない。

出力先はアドオンの `data/`。`auto-<server>-<character_id>-<UTC日時>-<6桁連番>.json` を世代別に保持する。tmpは取り込まない。以前のExportは出力・取り込み失敗時にも残る。手動の `//ff11export export` とファイル選択による取り込みも利用できる。アイテム移動・強化による所持品更新でも自動取得する。

## 初回のキャラ対応登録

下記のログイン観測で判明した値を、一度だけアプリ専用設定へ登録する。観測機能のアプリへの常駐組込みは未実装。値を推測して登録しない。

Windowerフォルダを設定済みの場合、自動取り込みはそこから導出したExport先を優先する。以下の `--directory` は既存の登録形式との互換用で、Windowerフォルダが未設定の場合に使用する。設定画面で配置先を変更しても、登録済みのキャラID・サーバー・USERフォルダの対応は保持される。

```powershell
.venv/Scripts/python.exe -m ff11reader.augment_sources --root "C:\path\to\FINAL FANTASY XI" --folder "観測したフォルダID" --character-id 123 --server 1 --directory "C:\path\to\Windower\addons\ff11export\data" --evidence "確認した観測記録の場所"
```

既定設定は `work/drafts/augment-sources.json`。インストール識別子・フォルダID・キャラID・サーバー・出力先・観測根拠を保存する。別の編集状態ディレクトリを使用する場合は `--config` でその直下の `augment-sources.json` を指定する。未確認やID・サーバーの不一致では手動・自動とも取り込みを停止する。複数インストール先はそれぞれ登録する。

## アプリ側の保存

保存先は `work/drafts/augment-observations/`。インストール識別子とフォルダIDの組をSHA-256化したファイル名を使う。`ff11-augment-store` v2でそのキー・`binding: [character_id, server]`・Export原文を一つのファイルへ原子的に保存する。自動表示名は保存したExportから導出し、個体情報と同時に公開する。旧v1も確認済み対応と照合して復元する。保存成功後は元Exportがなくても利用できる。

起動・ゲーム終了後の自動更新時に最新の所持品と再照合し、一致した収納だけを公開する。最新Exportが破損、出力先が不明、保存失敗の場合は前回取り込み済みの情報を保持して通知する。保存済みより古い取得日時では更新しない。同じ秒の出力は連番が最後のJSONを選択し、内容が変わっていれば更新する。個体情報と名前の更新は編集履歴・ゲーム原本から独立する。

## ログイン時のフォルダ特定調査

2026-11-11、利用者の依頼により、確認用マクロを用意せずゲームのファイルアクセスを観測する代替方式を調査した。一キャラの観測で対応を特定できたため、確認済み対応の登録と以後の自動取り込みに採用した。複数キャラ・同時起動の実機確認は未実施。

アドオン直下に `observe-login.enabled` が存在するときだけ、`login_observation.lua` がload/login/logout/unloadと、同じログイン世代の2・10・30秒後の状態を `data/login-observation/` のJSONへ保存する。記録はUTC時刻・イベント・世代・キャラ名・ID・サーバー。USERファイルの読取・編集やゲーム内操作は行わない。診断を止めるには有効化ファイルを除去してアドオンを再ロードする。

Process Monitorで `pol.exe` の `USER` 配下と上記診断出力へのアクセスを記録する。診断JSONを書いたPID・時刻を、同一PIDによるUSERファイルの正常な読取と照合する。列挙だけのアクセス、失敗した読取、別キャラへの切替を区別する。複数フォルダへの読取があれば候補をそのまま記録し、自動対応を確定しない。観測データはGit対象外のworkに保持する。

## ゲーム終了後の自動更新（DATA-007 / D-23）

起動時と使用中にWindowsのゲーム・PlayOnlineプロセスを確認する。起動中は終了待ち画面で操作を遮断し、終了後はファイル内容が安定してから必要な読み込みを行う。内容が同じならDATの再解析を省略し、Exportだけが変わった場合は個体情報だけを更新する。通常の利用に再読み込み操作は必要ない。

収納だけが変わった場合はアプリ内の編集・Undo/Redo・入力中マクロを保持する。ゲーム側でマクロや装備セットが変更され、アプリの編集と競合した場合は旧編集を保持して保存を停止する。ゲーム側を採用するときは、共通メニューの再読み込みから編集の破棄を確認する。

終了前Exportは通常のログアウト・終了イベントで取得する。強制終了時の未出力データは保証しない。ゲーム終了だけをDATとJSONの一致判定や書込権の取得とせず、収納照合と保存直前のプロセス・原本・排他検証を続ける。
