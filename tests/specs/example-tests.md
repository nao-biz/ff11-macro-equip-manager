# Example Test仕様

根拠: [要件](../../docs/README.md#仕様を調べる)と[設計上の制約](../../docs/README.md#仕様を調べる)。
本書は要件の結果保証と、現在採用する設計の検証仕様。キー・配置・内部方式を検証するケースは設計IDも根拠とし、設計変更時に見直す。正本との相違は[文書の管理](../../docs/README.md)の手順で解消する。記載ケースの実装・実行状況は別途確認する。

## 共通条件

- 全ケースは合成ファイル、一時ディレクトリ、固定辞書、偽プロセス一覧で実行する。実ゲーム・実レジストリ・実メモリ・ネットワークへのアクセスは拒否する。
- ケースの状態は独立させる。ゲームファイルへの書込回数、書込先、置換、バックアップ、作業保存、復旧イベントを記録する。
- `C1`、`C2`: 異なるキャラ。`B0`: 手持ち、`B1`: 金庫、`B8`: ワードローブ1、`B10`〜`B16`: ワードローブ2〜8。収納集合は`B0`〜`B16`。
- `I(C,B,P,T)`: キャラC、収納B、内部位置P、種類ID Tの所持品。位置は表示順から独立させる。
- `S(B,P,T)`: equip動作の装備枠。`X=1001`、`Y=1002`は合成辞書の別種類。Xの名前は`テスト装備`。
- 特記しない限り全17収納を読込済み、位置重複なし、数量不明、オーグメント取得不可。他の行・枠・持ち物は空。
- 空セットは16枠すべてkeep。マクロは名前と6行。空マクロは名前と全行が空。
- `W`: 作業値、`SAVED`: 保存済み値、`H`: 履歴、`K`: 履歴カーソル、`F`: ゲーム側の合成ファイル。
- `unchanged(F)`は全ファイルの存在・内容バイトが操作前と同一で、書込・置換・削除要求が0件。
- 表の期待結果はすべて必須。保留理由は対象を特定できること。実装の列挙名・文言の完全一致は要求しない。
- 将来機能のケースは実装前の受入仕様として保持する。未決定の振る舞いは末尾に列挙し、期待値を推定しない。

## DATA-003 個体情報の取り込み（D-16）

- 同収納の同ID・位置1と62のPath B/Cを出力から区別する。空収納を含む17収納を保持する。
- 読込未完了・ゾーン移動・ログアウト後の出力を拒否する。解析失敗は生データを保持する。
- 不正JSON・重複キー・重複収納/位置・範囲外・形式版違い・過大入力を拒否する。
- キャラ確認取消・読込失敗で補助情報を置換しない。収納不一致を表示し、該当収納の個体情報を利用しない。
- 取り込みと表示で編集履歴・原本が変わらない。再起動・再読み込み後は保存した個体情報を再照合して復元する。読込と検証はワーカーで実行する。

- DATA-003: 保存後に元のExportファイルを削除しても復元できる。キャラ・インストール間で混ざらない。保存失敗で旧情報を保持し、破損した個体情報だけ復元失敗とする。

- VIEW-002 / D-18: 装備パネル内のPath B/C、未取得・位置不一致時の空欄、インベントリのパネル/リスト切替と行クリックによる個体詳細を合成GUIで確認する。表示切替で編集状態・ゲーム原本が変わらない。

- VIEW-002 / D-18: 装備セットの全16枠はPathの有無によらず同じ高さとし、下段にPathを表示する。枠内の参照状態文字を省き、枠色とクリック先の説明を保持する。

- VIEW-005 / D-17・D-18: 固定HPと%を別集計し、潜在効果の次行・ペット効果・範囲値を集計外にする。対応が一致する個体のオグメだけ加算し、集計外の内訳を確認できる。

- VIEW-005 / D-17・D-18: 短剣スキル・魔命スキル・ウェポンスキルのダメージ・詠唱中断率・新規名称の数値を加算する。小数1.1と2.2は3.3になり、英語オグメの既知の別名は同じ名称にまとめる。「全項目・内訳」で全項目を読める。
