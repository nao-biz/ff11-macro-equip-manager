# マクロ再検証入力の分離と同時保存の計測

改修前コミット: f709e79。ゲームディレクトリを使わず、既存の実データ隔離コピーを毎回専用フォルダーへ複製した。`profile_mixed_save.py`で既存の`persistence_cycles.py`を包み、同一データ・equip/remove/keepの3操作を変更前後で実行した。計測器は本番コードへ追加していない。

## 原因と変更

マクロ保存直前の検証は全体ロード後にSnapshot全体をdeepcopyしていた。変更前はこのコピーが平均4.242秒、再ロードが平均6.069秒。必要な変更の再現と、入力所有権の確保が全体コピーに結び付いていた。

`macro_save_proposal.replay_macro_proposal`が、再ロード結果と計画の変更行・原本移動情報から独立した保存前後入力を生成する。コピーは対象キャラの変更マクロ・持ち物・種類辞書・取得元に限定する。元Snapshotと前後入力は互いに独立。保存計画の再生成と一致判定はmacro_savingが担当し、入力生成部品はロードやファイル書込を行わない。全体再ロード・依存ハッシュ検証・ロック・バックアップ・置換・復旧の処理は維持した。

## 同条件の結果

| 計測区間 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 計画＋保存・equip | 15.873秒 | 10.455秒 |
| 計画＋保存・remove | 14.498秒 | 10.262秒 |
| 計画＋保存・keep | 14.218秒 | 10.201秒 |
| 計画＋保存の中央値 | 14.498秒 | 10.262秒 |
| 全体コピー／限定入力生成の平均 | 4.242秒 | 0.533秒 |
| 保存直前の全体ロード平均 | 6.069秒 | 5.890秒 |

中央値で約29.2%短縮。各3操作の局所計測であり、全保存操作への一般化はしない。計測対象のread_bytes回数は前後とも4,878回で、ファイル検証を減らした改善ではない。入力生成に加えて、計画再生成側の全マクロ走査も限定された。

3回とも対象2ファイルだけを書き込み、全33,180マクロ・1,200装備セットの意味値、定型文、対象外ファイル、バックアップ、再起動相当の未保存変更なしを確認した。元コピー不変、監視違反0件。全体ロードは残り時間の主な部分で、今回の変更範囲には含めない。

## 構造と回帰検証

Import Linterのmacro-proposal契約を追加し、入力生成からロード・保存実行・UIへの直接依存を禁止した。domain-ui、save-state-storageと合わせた3契約およびsave_state.py内部アクセス禁止はローカル実行で適合。CIにも追加した。

静的解析は変更前を`work/architecture-before-mixed-save/`、変更後を`work/architecture-baseline/`に保存。モジュール75→76、直接依存235→237、protected-access28件・複雑度D以上40関数・他の集計警告数は不変。強連結成分で比較した循環グループも不変。検査の除外・しきい値緩和は行っていない。

追加テストは全体からの計画再生成との一致、入力の独立性、処理対象の限定、対象欠落、再ロード実行、不一致時の未書込を確認する。従来の収納Fix・定型文・コピー移動・保存失敗・復旧テストも継続する。

全体443テスト成功（104スキップ、107.452秒）。GUIを有効にする統合テストは今回は実行していない。設計正本69レコードの検証も成功。ログは`work/mixed-save-tests.log`。リモートCIの実行は未実施。
