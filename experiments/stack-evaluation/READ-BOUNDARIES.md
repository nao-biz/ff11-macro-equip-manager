# 読込方針・資料証跡・デコードの責務分離

改修前はd04b2bc。レビューで、共通ローダーの保存専用モードと、保存依存をそろえるために未使用モデルをデコードする結合を確認した。要件D-01の責務基準に照らし、以下を修正した。

| 担当 | 所有する知識・操作 |
| --- | --- |
| snapshot_loading | マクロ再検証に必要な対象ページと全収納を選び、読込要求を作る |
| CharacterReadRequest | キャラID集合・ファイル名集合の独立した不変値と入力制約 |
| LocalReader | 要求に従う列挙・読込・形式別デコード、読込した原本の指紋記録 |
| resource_catalog | 共通DATの論理ID群とFTABLEによる物理ファイル対応 |
| LoadedFiles | ロード時に観測した資料の所有、配置表の原本照合、明示的な共通資料の選出 |
| macro_saving | 選出された資料を保存依存へ加え、計画の生成と再検証を行う |

LocalReaderの`macro_scope`を削除し、一般的な`request`を受け取るようにした。装備だけなどの要求も同じ操作で処理でき、ローダーはマクロ保存なら収納も必要という方針を持たない。

通常・保存用ロードは`observe_resources`で共通資料の証跡を確保する。既読資料は指紋を保持し、未読資料はバイトを読んで指紋を記録する。保存用ロードはオーグメントのデコーダーを呼ばない。通常ロードでデコードできなかった資料も、原本の観測と意味値の生成を区別する。

保存計画の「USER外の取得元を全部依存にする」選出を廃止した。`LoadedFiles.shared_resources`がFTABLEを内容ハッシュで照合し、カタログに明示され、ロード時に観測した資料を返す。追加の無関係な読込は保存依存へ混入しない。共通資料には従来どおりオーグメント資産も含め、不要なデコードの削減と外部変更検出の範囲を分けた。
