# 技術構成の比較実験

本体の基点は `518f746`、復帰用タグは `checkpoint/before-stack-experiment-20261109`。
このディレクトリは計測・実験専用。本体の `ff11reader/`、起動経路、依存定義を変更しない。
候補の技術構成はここで比較し、改善を確認してから別の変更として本体への採用を判断する。

## 現行版のE2E計測

`maintain-specs`経由でPERF-001、D-10、D-15と既存のGUI回帰仕様を参照する。

```powershell
.venv/Scripts/python.exe -X utf8 -B experiments/stack-evaluation/baseline.py
```

実Tkウィジェットのキーイベント・ボタン操作から、本体の編集・保存処理、合成ゲームファイルへの書込みまでを通す。
1キャラ、400件/4,000件のマクロ、装備セット60件、持ち物0件。
各条件6周。初回を生データに残し、残る5周の中央値・最大値を集計する。小標本のためp95は報告しない。
保存対象は毎回マクロ名1件。キャッシュを空にした測定ではない。

- 編集確定、Undo、Redo、インベントリへの切替、マクロへの切替、保存確認、書き戻しを個別に測る。
- 計測の終点は操作コールバックが戻り、Tkの描画・待機イベントを処理した時点。OSの入力遅延や画面への実表示時刻は含まない。
- 10ms間隔のタイマーと操作終端でイベント処理間隔を測る。OS/GIL/GC/描画などの原因はこの値だけでは分離できない。
- 編集履歴の増分、Undo/Redo、編集確定後の入力先、タブ往復後の対象、保存後dirty解除と再読込した保存値を検証する。
- 実ゲーム検出のみ合成フィクスチャの仕組みで置き換える。保存・バックアップは実際に実行し、一時フォルダに限定する。
- 実IME、実ゲーム、OSの前面化、持ち物が多い場合、起動・再読込、異常系・連打はこのベンチマークの対象外。

生データは `work/stack-evaluation/baseline.json`、内部区間は `baseline-spans.jsonl`。
実行ごとに上書きするため比較に使う結果は別名で保存する。追跡対象の結果には合成計測値と環境情報のみを含める。

## 比較と採用の判定

以下は本実験の暫定判定基準であり、製品全体の性能保証とは区別する。

1. 同じマシン・データ・操作・保存差分で、現行版と候補を交互に実行する。採用判断には各3起動以上、操作ごとに合計20回以上の測定を行う。
2. 編集確定と書き戻しの中央値をそれぞれ30%以上短縮する。片方だけ改善した場合は改善範囲を限定して評価する。
3. 他の操作の中央値は10%または20msの大きい方を超えて悪化させない。イベント処理間隔の最大値は100ms以内を目標にし、測定回数を揃えて比較する。
4. 保存内容、定型文ID、Undo/Redo、フォーカス、操作順序、二重実行防止、失敗復帰の正しさを維持する。速くても状態や保存を壊す候補は採用しない。
5. UIを置換する候補でも、API単体の速度をE2E結果の代用にしない。フロント側の完了表示・次の入力受付までを測定する。

実験開始前に、同じ手順で再現する「遅い操作・イベント処理の間隔・正しさ」のベースラインを残す。
原因を言語に決めつけず、画面再構築、全体走査、保存前検証、I/Oなどの内訳を調べる。言語・フレームワーク変更そのものを成果にしない。
