# 保存入力の辞書コピー範囲

改修前コミットは434aee1。既存の隔離実データを専用フォルダーへ複製し、同じ`profile_validation_load.py`で保存区間を再計測した。ゲームディレクトリは使用していない。

## 検証境界の確認

現在の計画再生成は、全キャラの保存開始前の一致確認、各キャラの保存直前の一致確認、依存ファイルをロックした後のディスク状態からの再検証を担う。複数キャラ・部分成功・編集変更の拒否に関係するため、今回これらを削除・省略していない。

計画の再生成ごとにアイテム辞書全体をコピーしていた。保存前後の入力生成は1回の保存で6回、計測3操作では合計18回。ここに合計4.821秒（1保存あたり平均1.607秒）、ディスク再検証用入力の生成に合計1.597秒（平均0.532秒）がかかっていた。

## 責務と変更

`save_inputs`が保存入力の種類ID選出と独立コピーを担当する。編集状態の所有者は選択レコードを渡し、EditSessionは保存前後の種類IDの和集合を両側へ渡す。ディスク再検証用入力も同じ生成処理を使う。UIや保存を依頼する側へ辞書選別の知識を追加していない。

選出は装備部位ID、マクロがある場合の持ち物ID、明示的な定型文ID、マクロ原本・文字列原本にあるアイテム定型文IDを含む。原本は重なったFD候補とNUL以降も保守的に走査し、余分なIDの混入は許容する。正しいトークンかどうかは既存のデコーダー・保存時検証が判定する。種類7/9/10と旧言語バイトのID解釈をitem_tokensへ集約し、辞書解決と選出で共有した。

選んだ辞書レコードは全フィールドをdeepcopyし、表示用フィールド名の除外や共有可変辞書による短縮は行わない。新しい未所持アイテムの定型文、移動元原本、保存前後の種類差も保持する。
